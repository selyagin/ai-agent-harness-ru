# Модуль 4. Контекст и длинные задачи

## Проблема

Контекст модели ограничен. Если агент читает большой файл целиком или открывает десятки файлов, полезные сведения вытесняются шумом. Ответ становится дороже, медленнее и менее точным.

## Рабочая стратегия

1. Поиск: найдите символ, ошибку или название функции.
2. Отбор: выберите несколько файлов по совпадениям.
3. Чтение: берите только нужные фрагменты.
4. Сжатие: сохраняйте краткий вывод, а не полный текст каждого файла.
5. Проверка: перед изменением ещё раз убедитесь, что изучен правильный участок.

## Лимиты

Инструменты должны ограничивать количество результатов и размер ответа. Например: не более 50 совпадений поиска и не более 12 000 символов чтения. Если ответ обрезан, инструмент обязан сообщить об этом явно.

## Пример

Вместо «прочитай весь репозиторий» агент выполняет поиск `createUser`, читает файл с определением функции и только затем открывает файл, в котором она вызывается.

## Практика

Для задачи «найти причину ошибки» составьте план из трёх инструментов, не читая весь проект. Отдельно укажите, что вернётся в модель после каждого шага.
