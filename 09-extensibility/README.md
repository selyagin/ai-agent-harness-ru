# Модуль 9. Расширяемость

## Реестр вместо жёсткой прошивки

Не добавляйте каждый tool прямо в код агента. Реестр позволяет зарегистрировать инструмент по имени и собрать доступный набор для конкретной роли.

```ts
type Tool = { description: string; execute: (input: unknown) => Promise<unknown> };
const registry = new Map<string, Tool>();
registry.set('readFile', readFileTool);
```

Explorer может получить `readFile` и `searchText`, а executor — дополнительно разрешённую проверку. Так расширение не требует копировать agent loop.

## События жизненного цикла

Harness полезно делает наблюдаемым: `onToolStart`, `onToolEnd`, `onApprovalRequested`, `onError`. Через события CLI или web-интерфейс показывает ход работы, а журнал помогает разобрать ошибку. События не должны содержать секреты.

## Skills

Skill — пакет узких инструкций. В основном prompt храните лишь имя и краткое описание skill; полный текст загружайте, когда задача действительно относится к нему. Это называется прогрессивным раскрытием и экономит контекст.

Пример: skill `typescript-testing` содержит правила тестирования TypeScript-проекта; он нужен только при задачах о тестах.

## Практика

Спроектируйте skill `release-check`: опишите, когда он нужен, какие шаги предлагает и какие команды должны проходить approval.
