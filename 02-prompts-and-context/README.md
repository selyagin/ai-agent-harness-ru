# Модуль 2. System prompt и контекст проекта

## Зачем нужен system prompt

System prompt — это инструкция, которую harness передаёт модели до сообщения пользователя. Он не заменяет технические ограничения, но описывает порядок работы: сначала изучить проект, затем составить план, выполнять только разрешённые действия и честно сообщать об ошибках.

## Базовый шаблон

```text
Ты помощник по коду.
Сначала ищи нужные файлы, затем читай только релевантные.
Не меняй файлы и не выполняй команды с побочным эффектом без approval.
После изменения запускай доступную проверку и сообщай её результат.
Если задача неоднозначна — задай вопрос.
```

## AGENTS.md

В корне проекта можно хранить `AGENTS.md`: краткие правила именно этого репозитория. Например, где лежит код, какой пакетный менеджер применять и какую команду использовать для тестов. Harness читает этот файл и добавляет его в system prompt как проектный контекст.

Пример:

```md
# Project instructions
- Используй npm, не yarn.
- Исходный код находится в src/.
- Перед завершением запускай npm run check.
```

## Важно

System prompt — это рекомендация модели, а `safePath`, whitelist команд и approval — технические барьеры. Для защиты нужны оба уровня.
