# Модуль 7. Планирование и верификация

## План до действий

Перед изменением агент формулирует короткий план: какие файлы изучить, что изменить, какие проверки запустить. План не должен подменять работу: после каждого шага агент сопоставляет результат с задачей.

## Верификация

Утверждение «готово» допустимо только с наблюдаемым основанием. После изменения агент запускает подходящую проверку: `npm run check`, `npm test`, `npm run lint` или `npm run build`.

## Честный отчёт

Финальный ответ должен разделять факты: изменённые файлы, выполненные команды, успешные проверки, ошибки и то, что не проверялось. Не говорите «ошибка исправлена», если тест не запускался или упал.

## Пример плана

1. Найти обработчик формы через `search`.
2. Прочитать найденный файл и тесты.
3. Предложить изменение и получить approval.
4. Внести изменение.
5. Запустить `npm run check` и целевой тест.
6. Вернуть список изменений и фактический вывод проверки.

## Практика

Для задачи «добавить обязательное поле email» напишите план и выберите минимальную проверку. Укажите, что должен сказать агент, если проверка не проходит.
